# CI quality gates

PR CI MUST include lint/format, automated tests, build verification, dependency and secret checks, static application security testing where supported, and migration/API contract checks where applicable. Integration tests SHOULD use isolated databases and deterministic fixtures. CI failure blocks merge except a documented emergency procedure.

## Required checks baseline
The product adapter MUST name the real commands for:

- lint and format check;
- unit and integration tests;
- build;
- secret scanning;
- dependency vulnerability audit;
- static application security testing;
- database migration validation;
- API contract or OpenAPI drift check;
- coverage reporting;
- immutable artifact build.

## Workflow security
Use least-privilege workflow permissions, pinned trusted actions (full commit SHA for third-party actions), minimal secrets, and caching. Never expose production credentials to untrusted PR code. Separate CI validation from CD deployment. A production deployment or migration MUST NOT be cancelled by a newer commit; use a non-cancelling concurrency group.

## Dependency and secret hygiene
MUST enable automated dependency updates with an agreed patch SLA. MUST run secret scanning on every push and pull request; a clean working tree is not proof that a credential was never exposed.

The sample `templates/github/workflows/ci-example.yml` is deliberately fail-closed until stack-specific commands are supplied.
