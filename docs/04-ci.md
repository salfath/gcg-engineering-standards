# CI quality gates

PR CI MUST include lint/format, automated tests, build verification, dependency and secret checks, and migration/API contract checks where applicable. Integration tests SHOULD use isolated databases and deterministic fixtures. CI failure blocks merge except documented emergency procedure.

Use least-privilege workflow permissions, pinned trusted actions, minimal secrets and caching. Never expose production credentials to untrusted PR code. Separate CI validation from CD deployment.

The sample `templates/github/workflows/ci-example.yml` is deliberately fail-closed until stack-specific commands are supplied.
