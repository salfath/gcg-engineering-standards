# Release checklist

Attach evidence references and outcomes; a tick without evidence does not satisfy
a control. Use the [control register](../docs/12-control-register.md).

- [ ] Release owner/deputy and change window confirmed
- [ ] Reviewed per-component source SHAs, PR approval and exact-candidate required CI recorded
- [ ] Manifest and artifact digests generated by an approved locked CI build
- [ ] Database preflight, single-migrator lock and previous-app compatibility reviewed
- [ ] Backup freshness/integrity and current restore-drill evidence checked
- [ ] Same build verified in dev, exact digests verified in staging; UAT outcomes and approver recorded
- [ ] Product session/transaction preflight prevents races before mutation
- [ ] Production approval binds the same manifest/artifact digests
- [ ] Identical artifacts promoted without rebuilding or resolving dependencies
- [ ] Client/download digests and supported backend combinations verified
- [ ] Deployment result, migration result and actor/timestamps retained
- [ ] Smoke/readiness checks and post-deploy monitoring healthy
- [ ] Validated compatible rollback artifact and incident contact ready
- [ ] Open gaps/exceptions assessed; approvals are valid and not expired

Database restore/downgrade is not an automatic release rollback step. Record any
separate incident decision and potential data-loss reconciliation.
